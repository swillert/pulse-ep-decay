# pulse-ep-decay — examples

Cross-language reproducibility demos for the σ-resolution analysis
that is the core scientific contribution of this package.

The point of these examples is not to teach the API — that is what the
[unit tests](../tests/) and the
[`pulse_ep_decay`](../src/pulse_ep_decay/) docstrings are for — but to
show that the published σ values can be **independently reproduced**
on the same mesh, in different stacks, by anyone with the raw data.

| Folder           | Language | What it shows                                                    |
| ---------------- | -------- | ---------------------------------------------------------------- |
| (root, this file) | —        | Index and shared mesh helper.                                    |
| `sigma_fit_synthetic.ipynb` | Jupyter / Python | End-to-end on a synthetic icosphere: inject σ₀, run Heat-Method geodesics, recover σ̂ via `fit_gaussian_decay`. |
| `r/`             | R        | Python helper exports the radial profile to CSV; R reads it and re-fits the same Gaussian with `nls()`. σ̂ should match the Python pipeline to within the noise budget. |

The mesh used by every example is a 642-vertex icosphere with a 25 mm
radius — generated by [`_mesh_utils.py`](_mesh_utils.py). It is small
enough to run anywhere (no GPU, no pyvista build deps) yet detailed
enough that the Heat-Method gives realistic geodesic distances.

## Why a "reproducibility" example?

A reviewer asking *"can your σ values be reproduced without running
your code?"* should be able to point at one of these examples and
get an answer. The R workflow specifically uses

1. our Python pipeline only for the geodesic-distance computation
   (Heat-Method requires a sparse Laplacian — not trivial in R), and
2. **base-R `nls()`** for the fit itself — a different optimiser, a
   different package ecosystem, a different language.

Recovering σ̂ ≈ σ₀ from this chain is a stronger reproducibility
statement than re-running the same Python script.
